# Flood Exposure and Healthcare Facility Proximity in Cumilla, Bangladesh

An exploratory geospatial analysis of satellite-detected flood extent and mapped healthcare facilities during the August–September 2024 floods in Cumilla District, Bangladesh.

[![Python 3.11](https://img.shields.io/badge/Python-3.11-blue.svg)](https://www.python.org/)
[![Conda environment](https://img.shields.io/badge/environment-Conda-44A833.svg)](environment.yml)
[![License: MIT](https://img.shields.io/badge/code%20license-MIT-yellow.svg)](LICENSE)

## Project overview

This research portfolio project combines open satellite, administrative-boundary, and OpenStreetMap data in a reproducible Python workflow. It clips two UNOSAT flood-observation periods to Cumilla District, measures mapped flood area, and calculates Euclidean geographic proximity from mapped healthcare facilities to the nearest flood polygon.

The observation periods are analyzed separately; they are not treated as a controlled before-and-after comparison. The results describe mapped spatial relationships and do not measure road access, travel time, facility operation, or clinical service availability during the disaster.

Repository: [Tarunno360/cumilla-flood-geospatial-analysis](https://github.com/Tarunno360/cumilla-flood-geospatial-analysis)

## Personal motivation

The project grew from the author's experience supporting relief distribution during the August 2024 floods in Cumilla. That work highlighted the practical difficulty of locating inundated rural settlements without local aerial imagery and motivated an investigation of how open Earth-observation and volunteered geographic information can support transparent disaster analysis.

## Research objectives

1. Estimate the satellite-detected flood area within Cumilla District for each UNOSAT observation period.
2. Measure the straight-line distance from mapped healthcare-related facilities to the detected flood extent.
3. Provide a reproducible workflow with explicit coordinate systems, temporal separation, and data provenance.

## Study area

The study area is Cumilla District in Chattogram Division, eastern Bangladesh. Metric area and distance calculations use **WGS 84 / UTM zone 46N (`EPSG:32646`)**; geographic outputs use **WGS 84 (`EPSG:4326`)**.

## Data sources

| Dataset | Analytical role | Provider and attribution |
|---|---|---|
| Satellite-detected flood extent, Product 3954 | Flood polygons for two observation periods | [UNOSAT / UNITAR](https://unosat.org/products/3954), derived from Sentinel-1 SAR |
| Bangladesh ADM2 boundaries | Cumilla District study boundary | [geoBoundaries](https://www.geoboundaries.org/api/current/gbOpen/BGD/ADM2/), BBS and OCHA ROAP, CC BY 3.0 IGO |
| Healthcare-related facilities | Mapped facility locations | © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL 1.0 |
| Preliminary assessment, Product 3937 | Context for Cumilla City | [UNOSAT / UNITAR](https://unosat.org/products/3937) |

The repository retains the small OSM healthcare snapshot used for this analysis. Large downloadable source files and generated processed GeoJSON files are excluded from Git and are acquired or regenerated by the pipeline. Detailed provenance is recorded in [`data/source_data_manifest.json`](data/source_data_manifest.json) and [`docs/data_sources.md`](docs/data_sources.md).

## Methodology

1. Download the configured geoBoundaries, UNOSAT, and OpenStreetMap sources, or use complete locally cached copies.
2. Locate Cumilla District, repair invalid geometries, and project inputs to `EPSG:32646`.
3. Process the UNOSAT observation windows independently: 18–26 August 2024 and 28 August–4 September 2024.
4. Clip flood polygons to the district and dissolve overlaps before calculating area.
5. Calculate planar Euclidean distance from each mapped healthcare point to the nearest flood polygon.
6. Export period-specific statistics, machine-readable results, maps, and a research report.

See [`docs/methodology.md`](docs/methodology.md) for technical details. The configured primary period is `period_1`, represented by [`outputs/results.csv`](outputs/results.csv); [`outputs/results_period_2.csv`](outputs/results_period_2.csv) preserves the second-period facility results.

## Verified findings

| Observation period | Mapped flood extent | Share of mapped district area |
|---|---:|---:|
| 18–26 August 2024 (primary) | **472.16 km²** | **15.29%** |
| 28 August–4 September 2024 | **453.54 km²** | **14.68%** |

The retained OSM snapshot contains **86 mapped healthcare-related facilities** within the study boundary. For the primary period, 61 were within 500 m and 81 were within 1 km of the satellite-detected flood extent; none of the mapped points intersected the flood polygons. These computed values were checked against [`outputs/summary.json`](outputs/summary.json) and the retained CSV outputs. They are Euclidean proximity results, not evidence of disaster-time healthcare accessibility or operational status.

The full interpretation is available in [`reports/research_report.md`](reports/research_report.md).

## Installation using Conda

Prerequisites: Git and a Conda-compatible environment manager.

```bash
git clone https://github.com/Tarunno360/cumilla-flood-geospatial-analysis.git
cd cumilla-flood-geospatial-analysis
conda env create -f environment.yml
conda activate geotech-flood
```

The environment is defined in [`environment.yml`](environment.yml) and uses Python 3.11 with packages from `conda-forge`.

## Reproduction instructions

Run the complete workflow from the repository root:

```bash
python main.py
```

This downloads the configured public sources, writes them under `data/raw/`, regenerates `data/processed/`, and refreshes the analytical outputs. To use complete source files already present at the configured local paths:

```bash
python main.py --skip-download
```

Run the automated test suite with:

```bash
pytest -q
```

The download step depends on third-party services and may be affected by provider availability or rate limits. Source URLs and expected local paths are defined in [`config/config.yaml`](config/config.yaml).

## Scientific limitations

- Sentinel-1 SAR flood mapping can under-detect water beneath dense vegetation and in built-up areas because of radar-scattering effects.
- The UNOSAT layers show detected surface-water extent, not depth, velocity, damage, duration, or population exposure.
- The two products are observation windows, not controlled before-and-after measurements; differences may reflect acquisition timing and detection conditions as well as changing water extent.
- OpenStreetMap is dynamic and crowdsourced. The retained locations are not a complete facility census and do not confirm August 2024 operating status.
- Straight-line distance in a projected CRS does not represent routes, travel time, road passability, or actual disaster-time healthcare accessibility.
- The analysis has not been peer reviewed or independently field validated.

Additional caveats are documented in [`docs/limitations.md`](docs/limitations.md).
